# QQ 音乐评论卡片

输入歌名，得到一张（或几张）3:4 的图片：上面是专辑封面，下面是这首歌评论区里点赞最多的几句话，
排成电影字幕条的样子。版式沿用"视频字幕拼图"的思路：主图约 70%，4 条字幕条各约 7.5%，条间距为 0。

分工明确：**脚本负责确定性的事**（取数、清理文字、量字宽、断行、标记问题、渲染、逐字核对），
**你负责需要判断的事**（确认是哪首歌、挑哪几条评论、怎么分组、向用户解释）。
QQ 音乐的热评榜里混着广告、抄歌词、复制粘贴的梗，所以"挑"这一步比"做"更重要。

## 开始前

**Python 命令**：Windows 用 `python`，macOS / Linux 用 `python3`，后面一律加 `-X utf8`。下文写作 `<PY>`。
`<SKILL_DIR>` 指本 `SKILL.md` 所在目录的绝对路径，不要假设当前工作目录就是它。需要 **Python 3.10 或更新**。

**先做环境检查**：

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/check_environment.py" --network
```

缺什么它会说明。第三方库没装时，**先向用户说明再安装**，不要擅自装：

> 要用到一个开源的第三方库 qqmusic-api-python（GPL-3.0 许可，非官方）和 Pillow，会装进本技能目录下的 `.deps` 文件夹，
> 不动你电脑上已有的 Python 环境，删掉这个文件夹就等于卸载。可以安装吗？

得到同意后运行 `<PY> -X utf8 "<SKILL_DIR>/scripts/install_deps.py"`。

**第一次使用时，向用户如实说明一次**（不用每次重复）：
- 这是**非官方**接口，不是腾讯提供的开放服务，可能随时失效，也可能不符合 QQ 音乐的服务条款，请自行权衡；
- 这个库为了访问 QQ 音乐，会在运行时**模拟一台 Android 设备**并向腾讯服务器注册（不读取登录信息，不需要账号）；
- 成品仅建议个人学习、分享使用，**不要商用**；评论的著作权属于评论者。

**运行位置**：需要在用户自己的电脑上运行。网页版或受限沙箱连不上 QQ 音乐，这时如实说明，不要硬试。

## 流程

产物统一放在 `qqmusic_cards/<歌名>/` 下（用 `--out-dir` 改）。下文用 `OUT` 表示这个目录。

### 1. 确认是哪首歌

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/qq_fetch.py" search "歌名 歌手"
```

候选里会标出"歌手匹配"、"可能不是原版"（Live、DJ、翻唱、伴奏等）和"★推荐"。

- 有一个 ★推荐（歌手匹配、不是衍生版本）：直接用，并在回复里说一句选了哪首。
- 用户没给歌手、同名歌很多，或候选都是衍生版本：把前几个候选列给用户，**问一次**选哪首。不要替用户猜。
- 候选里没有任何一首的歌手与用户说的相符：说明可能没有原唱版权，搜到的多是翻唱，请用户决定换歌还是用翻唱版。

### 2. 取封面和热门评论

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/qq_fetch.py" fetch --keyword "歌名 歌手" --song-id <歌曲ID> --out-dir "OUT"
```

默认取 6 页（约 90 条）。生成 `OUT/song.json` 和 `OUT/cover.jpg`。留意输出里的封面像素和"歌词比对"状态
（歌词比对用来识别抄歌词的评论；取不到时只是少了这层保护，要在选评论时更警惕）。

### 3. 整理候选

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/prepare_comments.py" --song "OUT/song.json" --out "OUT/candidates.json"
```

打印一张候选表：**编号、点赞数、字数、占几条字幕条、标记、内容**。
- 标记里 `【…】` 是**硬标记**（广告、联系方式、抄歌词、表情/音频代码、占位刷屏、字体缺字），默认不该选；
  `（…）` 是软提醒（疑似AI腔、可能提到具体人名）；还有"重复于/近似"、"太长"、"非标点断行"。
- 太长的评论下面列出"截取片段"（编号如 `2.2`）。
- 作者写的换行会直接变成字幕条的断行，所以分行的短诗占条数 = 行数。
- 终端默认只打印前 40 条，完整内容在 `candidates.json` 里；需要时去读。

### 4. 选评论并分组（需要判断，先读 `references/selection-rubric.md`）

决定做几张卡、每张放哪几条，写成 `OUT/cards.json`：

```json
{"cards": [{"name": "反差", "quotes": ["1", "3", "26", "27"]}]}
```

- 只写**编号**，不要自己重新打字，文字由脚本填入，这是保证"原文不被改动"的关键。
- 每张卡所选评论占条数加起来要**正好等于 4**（候选表"占条"一列相加）。
- 打包建议只是机械凑数，它不看主题，也看不出梗和隐私，不能直接用。
- 默认只做**一张**最强的卡，用户要更多再加。
- 选完给用户一句话预览（主题 + 每条评论和点赞数），不必等确认，除非用户想先看。

### 5. 渲染

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/render_card.py" --song "OUT/song.json" --candidates "OUT/candidates.json" --cards "OUT/cards.json" --out-dir "OUT/cards"
```

渲染前它会先校验编号是否存在、条数是否凑满、有没有重复、是否太长，报错时按提示改 `cards.json`。
默认不覆盖已有成品，需要替换时才加 `--overwrite`。版式和可调参数见 `references/layout-spec.md`，需要调整时才读。

### 6. 质检并有界返工

```bash
<PY> -X utf8 "<SKILL_DIR>/scripts/qa_check.py" --manifest "OUT/cards/render_manifest.json" --song "OUT/song.json"
```

自动质检会重新核对：卡面文字与评论原文是否**逐字一致**（原文只经过去掉表情符号、不可见字符这类符号层面的整理，
QA 也会重新核对这一步）、版面是否超出、封面放大倍数、每条字幕条是否真有字、所选评论有没有带硬标记。
有 FAIL 必须处理，WARN 要评估并在交付时说明。

**然后用眼睛看**：逐张打开成品，确认封面完整不变形、字幕条文字清晰、手机缩略图大小下也读得出。
自动检查不能替代这一步。如果当前环境看不了图片，如实告诉用户"只做了自动检查，没有肉眼检查"，请用户打开 `contact_sheet.jpg`。

发现问题只改对应的那一个变量（排障表在 `references/layout-spec.md`）。连续三轮不满意，换一组评论或如实说明限制。

### 7. 交付

告诉用户：成品图片路径、总览图路径、每张卡里每条评论的编号和点赞数、**你放弃了哪些高赞评论以及原因**、
哪些评论去掉过表情符号（卡面与原评论不完全一样）、封面清晰度等任何 WARN。没有逐张检查过的图片，不要说"完成"。
用户要发布时提醒：评论著作权属于评论者，封面和歌曲版权属于相关权利方，请勿商用；卡片上只有歌名、歌手和来源标注，没有评论者信息。

## 不能破的规则

- **卡面上的每个字都必须是评论原文。** 不改写、不缩写、不合并、不润色，只做断行。读者看到的"热评"必须真是评论区里的话。
- **不显示、不保存评论者信息。** 昵称、头像、用户标识（`nick`、`avatar`、`encrypt_uin`）一律不读取、不写入任何文件、不出现在成品里。
  也不要去猜或推测某条评论是谁写的。
- **不输出歌词。** 歌词只在内存里用来比对，不写入文件，也不要在回复里复述歌词内容。
- **点赞数是真实数据**，只能照抄，不能估算或美化。
- **不选带硬标记的评论**，除非有充分理由并向用户说明。
- **不覆盖用户已有的文件**，除非用户明确要求替换。

## 停止条件

出现这些情况时，停下来说明原因和选项，不要硬做：

- Python 低于 3.10，或用户不同意安装第三方库。
- 连不上 `qq.com` / `tencentmusic.com`（不在本机、被网络限制）。
- 搜不到歌，或这首歌没有取到热评（冷门歌）。
- 没有可用评论凑满一张卡（硬标记、重复、太长的都排除后）。如实告诉用户，可以放宽到 `--flex`（3–6 条）、多取几页（`--pages`）或换歌，
  不要塞无关的话凑数。
- 库返回的数据格式变了（取数时出现校验失败）：说明接口可能已被调整，不要绕过去硬做。
- 用户要把成品用于商业用途：说明版权和平台条款不允许，请自行评估风险。
